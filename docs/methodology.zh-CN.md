# 为什么是这两个维度？

[返回首页](../README.md) · [English](methodology.en.md)

本项目的四象限是选方法的启发式，不是逻辑学定理或经过统计验证的通用分类。下面区分原始研究与我们自己的工程归纳；本文解释方法，不复制论文或声称作者为本项目背书。

## 先把两个问题分开

| 维度 | 实际在判断什么 | 它改变哪项设计 |
|---|---|---|
| 横轴：信息处理需求 | 输入、规则与适用条件是否清楚稳定，能否直接按规则处理？还是需要理解多变表达、检索或补充事实？ | 规则处理是否足够，需不需要模型理解、检索、人工澄清 |
| 纵轴：流程可预设程度 | 下一步和关键分支能否事先写出？还是必须根据新发现临场决定接下来查什么、做什么？ | 固定工作流是否足够，需不需要逐步分析、自适应控制或人工探索 |

当前图中的“信息不确定”是宽泛的教学简称，不能把所有情况当作同一种未知。判断时必须分别标注：①表达/格式多变；②缺少事实；③材料冲突或不可信。第一种可尝试理解与抽取；第二种需要补证据；第三种需要权威版本与核实。向量检索和更强模型都不能自动消除后两种问题。

## 纵轴最容易误解的地方

固定流程可以有很多步骤、分支、循环、并发和失败重试。只要规则能提前确定，就不因为看起来复杂而变成 Agent。

- 固定：金额低于某值走 A，超过走 B，缺字段退回。分支很多，判断规则仍已知。
- 自适应：先查销售数据，发现集中在一个渠道，再决定调查该渠道的价格、库存还是记录异常。下一项有价值的调查依赖新发现，不能仅由现有固定业务规则列出。
- 自适应不等于必须用大模型：优化算法、搜索算法或专家也可能承担。应比较可验证的现成方法。
- “探索业务目标”和“执行一个已明确目标时动态选择动作”分开。连要改善什么都没定时，先澄清目标。

## 为什么保留两个轴

这是工程上的两项不同决策：处理信息的能力，与控制流程的方式。它们不要求统计独立；只要不同组合会改变起步方案，就有助于选型。

| | 流程可预设 | 流程需自适应 |
|---|---|---|
| 信息可直接按规则处理 | 表格合并与已知规则统计（Q1） | 数据齐备、调查顺序依结果调整（Q3） |
| 信息需理解或补充 | 按固定字段理解不同写法的反馈（Q2） | 需求和信息都不明确的探索（Q4） |

两条连续维度做高低划分，得到四个组合，这是逻辑上的组合表；划分点是人为的，不是自然界只有四种任务的证明。允许中间状态、未知和混合；分类应有理由，不能给出伪精确分数。

## 理论与工程资料怎样支持它

### 主要理论参考：任务特征与组织方式的匹配

Perrow（1967）讨论例外情况多少与问题搜索过程的可分析性，用不同组合研究工作和组织结构。这支持“不要只用单一复杂度概括任务”的思路；本项目的输入信息轴和流程控制轴并不等同于他的原始变量，四类名称也不同。

来源：[原论文书目信息与稳定入口](https://www.jstor.org/stable/2091811)，*A Framework for the Comparative Analysis of Organizations*。核查了原论文内容；这里为中文意译和应用归纳，不是引语。

### 补充：任务不确定性与信息处理

Galbraith（1974）的组织信息处理观点解释了：任务越难提前理解和安排，执行中越需要处理信息并协调。我们据此提醒使用者先看缺什么信息、怎样补齐；这不能推出本项目的精确两轴或四种技术路线。

来源：[作者网站论文](https://jaygalbraith.com/wp-content/uploads/2024/03/infoprocess1974.pdf)。理论原义与本项目的启发式分开。

### 工程对应：固定工作流与自适应 Agent

Anthropic 的工程文章按预设代码路径与模型动态决定过程来区分 workflows 和 agents。这个区别直接帮助解释纵轴。文中同样主张从简单方案开始；它没有提出或验证本项目的四象限。

来源：[Building effective agents](https://www.anthropic.com/research/building-effective-agents)（2024；工具清单已变化，用作架构概念参考）。

## 不能由这张图推出什么

- 不判断项目是否值得投钱，另看频率、质量、风险、全成本和实际收益。
- 不决定是否允许自动执行，付款、审批和对外发布等动作另设授权与接管规则。
- 不把材料结构化等同于事实正确，也不把模型自报置信度当成可靠概率。
- 不假设四个组合一定出现；如果同一任务的两个判断始终不可区分，先重新拆分任务。
- 反例：复杂但规则完整的计算，可能适合确定性算法；不能因步骤多或运行时有分支就推荐 Agent。
