# 选模型：先过业务验收，再比较全成本

[首页](../README.md) · [English](model-selection.en.md) · [评测表](../templates/model-evaluation.csv)

不要给每个象限指定一个唯一模型。聊天产品、底层模型、工作流平台和部署方式是不同层：同一平台可接不同模型，聊天产品可用的能力也不保证对应 API 有同样能力。

## 按能力列两个候选

| 实际任务 | 先比较的能力 | 必须测什么 |
|---|---|---|
| 固定规则计算 | 表格/代码往往足够；模型可辅助搭建 | 数值正确、边界条件、异常；不默认逐次调用模型 |
| 固定字段提取与分类 | 成本可接受的通用文本模型，中文与结构化输出能力 | 漏项、多标签、缺失值、格式、来源证据 |
| 图片/PDF/表格理解 | 多模态或文档解析能力；解析与回答分别测 | OCR、跨页表格、单位和字段丢失 |
| 检索问答 | 检索/权限/版本机制加能依据材料回答的模型 | 检索命中与答案依据分开测、冲突/无答案处理 |
| 多步分析与工具调用 | 推理、工具参数、遵循预算和恢复能力 | 成功完成任务、错误工具操作、轮数、耗时和接管 |

地区、数据政策、维护能力、预算和访问条件先筛选；不能依据国家或品牌直接判断适合。没有实测就给条件候选，不写“最佳”。

## 可从这些官方目录找当前候选

- [阿里云 Model Studio / Qwen 模型目录](https://www.alibabacloud.com/help/en/model-studio/models)：按所需文本、多模态等能力选当前可用候选，确认区域和部署条件。
- [DeepSeek 官方 API 文档](https://api-docs.deepseek.com/)：核对当前模型标识、能力、用量与价格链接。
- [Claude 平台](https://platform.claude.com/docs/en/about-claude/models/overview)：核对当前模型能力、接入与地区条件。不要因本项目引用了 Anthropic 的架构文章，就推定其模型在本任务胜出。

这些是候选入口，不是全市场排名；未逐一做模型横评，不冻结可能过时的价格和版本。核查日期 2026-11-07；实际采购前复核。已有聊天工具能完成时，先用它，不强制换服务或开通 API。

## 一个可执行的小比较

1. 从获授权的真实任务中选择代表样本，覆盖正常、缺失、冲突、长材料和关键异常；少量样本用于起步，不推断总体准确率。
2. 事先写出参考结果或人工验收规则，按业务严重度设通过条件。先过质量门槛，再比较钱与时间。
3. 同一任务、输入、工具权限和预算下比较两个可用候选；记录模型版本、参数、日期、提示词版本。多次运行检查波动，样本与次数由风险和预算决定。
4. 用一批样本调整提示词，另一批保留作检查，避免只记住演示题。模型打分可辅助，关键错误由人或确定规则核验。
5. 记录：是否完成、重要遗漏、无依据事实、格式/工具错误、质量合格与否、耗时、输入输出 token、重试、人工分钟数、实付费用。
6. 只在业务质量合格的方案里比“每个验收通过交付的全成本”：该批全部调用、失败重试、工具与人工检查成本 ÷ 通过数。通过数为 0 时不报一个漂亮平均值；同时报告失败与风险。

人工小时折算值是资源成本估计，不等于现金支出。保留模型/工具运行费用与人工成本口径，防止和 ROI 里的支出重复相加。

只有简单候选持续达不到验收时，再提高模型能力、增加检索或改流程；不要只因为“更贵/更新”就升级。把简单任务路由给便宜模型、复杂任务升级，需要真实错误检测与回退机制，不能只相信模型自报置信度。

参考：[Demystifying evals for AI agents](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)。本项目的记录表和选择流程是应用归纳，不是对任何模型的性能认证。
