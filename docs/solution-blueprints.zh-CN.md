# 四条起步路线：从输入到验收

[首页](../README.md) · [English](solution-blueprints.en.md)

以下是**合成设计蓝图**，不是已部署的客户案例、可直接导入的模板或收益证明。选择一条路线，从小样本开始；平台功能重叠，不对应唯一象限。

## A｜规则报表：先不用运行时 AI

- 输入：格式一致的表格、去重键、金额与日期规则。
- 流程：校验字段→规则清洗→合并/计算→异常清单→人工核对。
- 简单版：现有表格功能或脚本。重复跨系统流转时才比较 [n8n](https://docs.n8n.io/)。
- 对照点：规则清楚的执行可为 Q1；缺规则先请负责人确认。
- 验收：控制总数、重复项、金额单位与异常记录，错误可追溯；失败不静默交付。

## B｜反馈报告：固定流程里加入理解

- 输入：脱敏反馈、已确认标签和输出字段。
- 流程：读取→模型提取标签/原文/未知→人工确认→表格统计→报告草稿。
- 简单版：现有聊天与表格。重复批处理时比较 [Dify](https://docs.dify.ai/en/home) 的应用/工作流，或业务系统流转主导时比较 n8n；不是两者必须叠加。
- 对照点：理解可能 Q2，确认后的统计可能 Q1。
- 验收：重要遗漏、无依据原因、多标签计数口径、人工分钟数；不自动对客户发报告。

## C｜企业资料问答：资料可信与权限先行

- 输入：获授权且有版本/负责人的政策材料、可回答范围、用户访问权限。
- 流程：身份/权限→检索允许资料→回答附依据→无答案/冲突升级→日志与反馈。
- 简单版：少量文件人工辅助检索；多人反复查资料时再比较 Dify 知识检索应用。
- 对照点：可在 Q2 起步；版本冲突需要业务负责人处理，不能让模型猜哪个政策有效。
- 验收：查到了正确材料吗、答案受材料支持吗、是否越权、过期/无答案怎么办。检索正确与生成正确分开测。

## D｜动态调查：先人工观察，再讨论 Agent

- 输入：明确调查目标、授权数据/只读工具、执行预算。
- 流程：提出待核实假设→调用查询/计算→检查证据→决定下一步→限制轮数/人工接管→带来源结论。
- 简单版：人带工具分步做；需要持久状态、恢复与接管时比较 [LangGraph](https://docs.langchain.com/oss/python/langgraph/overview)，或需要可视化应用时比较 Dify Agent 节点。
- 对照点：数据较清楚而路径自适应可为 Q3；目标也没定时先做 Q4 的澄清探索。
- 验收：证据是否支持结论、是否错误调用、是否超预算、能否停止/接管。先只读，不由示例推导任何外部写入授权。

## 为什么没把所有框架列满

工具长名单不能代替方案。本次主要核查 n8n、Dify、LangGraph 的官方能力入口（2026-11-07）。Coze、FastGPT、Make、Zapier 等可按现有环境补充，未做完整横评。推荐时最多保留两条解释清楚的路线，注明账号、部署、数据授权、维护、费用和许可条件。某些工具有独立或限制性许可，本仓库的 MIT 不等于替它们授权。
