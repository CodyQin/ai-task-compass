# Learn by role and deliverable

[Overview](../README.md) · [中文](learning-paths.zh-CN.md) · [Routes and official resources](technical-routes.en.md)

Learning recommendations, not fixed-time career or venture promises. Progress through small checkable outputs.

| Role | First deliverable | Next deliverable | Deepen only if needed |
|---|---|---|---|
| Owner/business/creator | One real process, output, evidence and acceptance owner | Existing-tool trial with review/rework records | RAG for justified repeated retrieval; workflow for recurring handoffs; establish maintenance |
| PM/consultant | Problem brief, flow, access, output contract and exceptions | Representative cases, two-route tradeoff and pilot PRD | Integrations, evaluation, logs, intervention, rollback and full cost |
| Developer/AI engineer | Inputs/outputs, validation and one restricted tool/sample | One task-relevant official RAG or workflow starter with checks | Agents for adaptive control; LangGraph for recovery/state; harness design for continuity |
| Founder | User/buyer distinction and a falsifiable demand assumption | Bounded learning experiment with time/cash exposure | Technical route and commercial assumptions when evidence justifies it |

Common dependencies: [problem brief](../templates/PROJECT-BRIEF.md) → authorized/versioned data and output contract → simplest existing-tool version → one relevant [route](technical-routes.en.md) → [evaluation records](../templates/model-evaluation.csv) → [delivery ownership/checks](../templates/DELIVERY-CHECKLIST.md).

Official resources are entry points, not a claim that every tutorial was executed or every course compared. Accounts, fees, versions and region may differ. Do not copy credentials or run tutorials against production data by default. The learning output is your checked sample, record and next decision, not merely a list of tools studied.
